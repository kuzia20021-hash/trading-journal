# trading-journal

Личный торговый журнал, риск-менеджмент и бэктест-харнесс.
Адаптация архитектуры [TauricResearch/TradingAgents](https://github.com/TauricResearch/TradingAgents):
мульти-агентная схема анализа + честный point-in-time бэктест.

## Что здесь

- `src/risk.py` — риск-менеджмент: размер позиции от свободной маржи и риска в R, стоп по ATR.
- `src/backtest.py` — бэктест без look-ahead: решение на дату D оценивается по закрытию бара ПОСЛЕ D.
- `src/stats.py` — статистика журнала: винрейт, средний R, максимальная просадка + бейзлайны (buy&hold, MVO).
- `src/env.py` — Gym-стиль торговая среда (state → action → reward → state) по мотивам FinRL: штраф за oversized-позицию, режим turbulence, честный счёт капитала.
- `src/regime.py` — режим рынка и риск-скейлинг: turbulence index + просадка от максимума → размер позиции режется вдвое в высоком риске.
- `src/live_regime.py` — живой режим по реальной истории (Yahoo Finance, без ключей): считает turbulence и просадку за 60 дней → рекомендуемая маржа. Используется перед каждой сделкой.
- `journal/trades.csv` — журнал сделок (вход, стоп, цель, результат).
- `data/observations.csv` — таблица наблюдений до входа в сделку.
- `docs/agents.md` — роли агентов (техника, новости, сентимент, фундаментал → бык/медведь → риск).

## Принципы

1. Решение принимается на закрытии бара D, оценивается по закрытию следующего бара.
2. Никаких данных, опубликованных позже даты решения.
3. Риск на сделку фиксирован в R, размер считается от маржи, а не наоборот.
4. Логировка обязательна: сделка без записи в журнал = ошибка процесса.

## Использование

```bash
python src/stats.py journal/trades.csv
python src/risk.py --equity 100 --risk-pct 1 --entry 87.02 --stop 89.65 --leverage 5
```


## FinRL: что взято

Источник: [AI4Finance-Foundation/FinRL](https://github.com/AI4Finance-Foundation/FinRL) (MIT).

Взято:
1. **Среда как объект** — торговля описана как Gym-среда с явным разделением state/action/reward.
2. **Turbulence index** — риск-скейлинг: при высокой волатильности размер позиции режется.
3. **Бейзлайны** — стратегия сравнивается с buy&hold и MVO, а не с «отсутствием сделки».
4. **Ограничение позиции** — штраф за превышение максимальной доли капитала в позиции.

Не взято: обучение DRL-агентов (A2C/DDPG/PPO/TD3/SAC) — для этого нужны тысячи сделок в истории, а не единицы.

## FinRL-X / FinRL-Trading

Оригинальный FinRL сам переводит пользователей на форк `FinRL-Trading` — там модульная архитектура, `bt`-движок бэктестов, Alpaca-интеграция. Если задача вырастет до лайв-торговли, смотреть надо туда.


## Живой режим рынка

`src/live_regime.py` тянет дневные закрытия из Yahoo Finance и считает режим:

```bash
python src/live_regime.py --ticker BTC-USD --margin 33
```

Просадка считается по скользящему окну в 60 дней, а не от годового максимума:
на падающем рынке годовая просадка всегда огромная, и фильтр режет размер постоянно.

Порог: turbulence > 0.5 **или** просадка за 60 дней > 12% → размер позиции режется вдвое.
